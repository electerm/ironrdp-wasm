# 2026-10-22

## CI: npm publish workflow

- Added `.github/workflows/npm-publish.yml` (modeled on `~/dev/electerm-sync`): `check` job
  compares `package.json` version against the registry, `publish` job builds and publishes.
- Auth is npm **trusted publishing** (OIDC): `permissions.id-token: write`, `npx @jsdevtools/npm-publish
  --access public --provenance`, **no NPM_TOKEN secret**. Requires configuring the trusted publisher
  on npmjs.com (electerm / ironrdp-wasm / `npm-publish.yml`) — user does that side.
- Build steps this repo needs beyond electerm-sync: rustup toolchain `1.99.1` + `wasm32-unknown-unknown`,
  wasm-pack `0.15.0` from the official prebuilt musl tarball, then `node bin/prepare-ironrdp.js`
  (separate step so `.ironrdp` can be cached) and `npm run build`. No `npm ci` — the package has no
  dependencies and `package-lock.json` is out of sync with `package.json` (lock still lists vite).
- Caches: `.ironrdp` keyed on `bin/prepare-ironrdp.js`+`patches/**` (stamp makes stale restores
  self-healing), and cargo registry + `.build/target` + `~/.cache/.wasm-pack` (wasm-bindgen-cli compile
  ~2 min, binaryen download) keyed on manifest/src/prepare/patches.
- Verified the whole job on a clean `ubuntu:24.04` in docker (arm64 colima): rust + wasm-pack install,
  prepare, `npm run build`, artifact check and `npm pack --dry-run` → exit 0, 8 files, pkg/*.wasm 4.1 MB.
  Only local-network blocks hit (github.com/binaryen fetch), not present on GH runners.
- `pkg/` is gitignored but ships thanks to the `files` field — confirmed by `npm pack --dry-run`.
- Registry currently has 1.1.0; `package.json` is 1.2.0, so the first push to main publishes 1.2.0.
